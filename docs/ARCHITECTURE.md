# Architecture

Document Workflow combines a native OpenCloud Web extension with one Node companion. It follows the [OpenCloud app skeleton](https://github.com/opencloud-eu/web-app-skeleton) and uses Web SDK 8.2.1. OpenCloud remains the owner of document files, resource identities, tags and permissions.

## Web extension

`src/components/NativeWorkspace.vue` attaches the host session; `src/state/workspace.ts` sends authenticated same-origin requests. `src/views/` contains Inbox, Documents, Activity and Settings. PDF.js worker, fonts, CMaps and codecs are packaged locally. The store ZIP has `manifest.json` at its root; the coordinated installer retains an internal `document-workflow` wrapper matching the app ID. The host router is shared rather than bundled privately.

## Companion

`companion/server.mjs` exposes `/_workflow/api/` behind the existing HTTPS proxy. The API dispatches to named handlers only after common same-origin, account identity and document-Space checks. Related verify/reconcile endpoints share handlers with explicit operation flags; unknown and inherited object names are not routes. It validates current identity and authorized Space access through OpenCloud Graph/DAV. Caller-supplied account identifiers do not establish ownership. Credentials are not returned to the browser or stored in browser storage.

The companion owns a private SQLite journal for settings, metadata, queue state, proposals, approvals, mutation intents and activity. A separate `.runtime.sqlite3` sidecar holds an exclusive process-lifetime SQLite transaction on the same private local volume. The operating system releases it after an unclean stop, so recovery never relies on a container hostname or reused PID. Only the owning process may open a writable ProposalJournal; handles in that process share active ownership sets. Interrupted proposal reads require retry, and abandoned operation locks can be reclaimed. Approval records and uncertain write intents are not reset. Never unlink the sidecar while a companion is running. Original live documents stay in OpenCloud. Demo mode instead uses synthetic PDFs in an isolated journal and cannot access live OpenCloud files.

A durable intake loop checks upload stability, prepares bounded jobs and retries transient failures. OpenCloud App Tokens are stored separately from the journal and are required for reliable unattended access. They are excluded from journal backups. Backup snapshots and manifests can be uploaded to a configured OpenCloud folder; administrators must restrict access because snapshots include workflow records for users served by this companion.

## Processing and writes

Poppler extracts text; missing-text pages can use local Tesseract. Pages with fewer than 200 non-whitespace embedded characters also receive OCR when Poppler reports a single raster image covering at least 45% of the page. Embedded text is retained alongside that OCR. Short text-only pages do not trigger this supplement. If standard OCR returns only whitespace, one bounded retry uses Tesseract’s built-in Sauvola thresholding. Existing nonempty OCR is not replaced by a competing result. This adds no service or package dependency. Original PDF bytes are never rewritten. Local Ollama and compatible hosted endpoints use explicit task routing. Hosted transmission requires operator configuration and user consent. There is no implicit provider fallback.

Model output must fit the schema and quote extracted page text. Dates, paths, categories, field values and tags are validated before proposal acceptance. Text is untrusted input. Literal quotes cannot establish semantic truth, so human review is the default.

A manual review is a separate bundle with no accepted AI proposal and a bounded reason (evidence, date, capacity or unreadable text after OCR). It requires an explicit destination; tags are optional, and automatic processing never authorizes it. The worker does not convert transient provider failures or changed source identity into a manual result.

Local Ollama requests disable input truncation and context shifting. Requests within a conservative whole-message byte budget can use legacy servers. Larger requests require a successful synthetic check that the actual installed model/server rejects oversized input; this check uses no document data, is keyed by endpoint/model digest/server version and expires. Returned token metrics are required for these larger requests and cannot exceed the configured window. Every correction request is budgeted again. Local request deadlines scale with source length from two minutes to a maximum of five minutes; they never wait indefinitely. Unknown/unsupported servers and cloud routes retain conservative preflight; connection failures and busy services are never converted into capacity results. No page is dropped, no model limit is raised and no provider fallback is enabled. Native behavior was tested against Ollama 0.40.13; see its [request flags](https://github.com/ollama/ollama/blob/v0.40.13/api/types.go) and [chat routing](https://github.com/ollama/ollama/blob/v0.40.13/server/routes.go). A read-only per-field inspection of saved model output can show verified claims alongside precise validation failures. This advisory inspection cannot create an accepted proposal, approval or mutation. Raw model responses are never returned to the browser. Unique case-only and layout-whitespace matches restore the exact source span, including wrapped titles. Only tab/newline wrapping is rendered as spaces in filenames; existing ordinary spacing is preserved. Ambiguous matches, changed letters/digits and other control characters remain invalid.

The model receives only category/tag options with potential support under the saved matching rules. It still receives every source page, and the recorded review contains all saved rules. Spaced CJK glyphs can match a configured substring within one source line; different letters, digits, lines and evidence passages are not joined. Multi-character Japanese name aliases use the same layout handling while one-character name safeguards remain unchanged.

The model receives bounded complete date passages extracted from the same source pages. These are untrusted evidence candidates, not instructions or proof of the date's meaning. Calendar validation still rejects ambiguous conventions, invalid dates and incomplete OCR. A printed timestamp may supply its one unambiguous date span; multiple different dates remain held.

Potential-duplicate detection streams the latest scoped document inputs and compares printed identifiers, dates, amounts and text overlap. It never borrows metadata between documents or classifies a similarity match as byte-identical. Current OpenCloud access, resource identity and ETag are checked before exposing comparison links. Automatic processing holds on a candidate; similarity cannot authorize Trash.

Bulk re-preparation pins resource identity and ETag before OCR/model work, creates a fresh manual review attempt and retains previous records. Global processing controls also cover preparation/conversion batches: pause finishes the active item, cancel skips remaining queued items, and retry-all repeats only held preparation reads. Uncertain conversion, filing and metadata writes require their existing reconciliation paths. Preparation rows retain a bounded failure stage and completion timestamp. Current queued/running source-pinned attempts suppress older preparation errors; a later review supersedes an old batch error. Filing-intent and conflict warnings take precedence. The bulk preparation view polls read-only status and opens the exact result job; conversion/file verification remains explicit.

Approvals bind to the exact source identity, hash, ETag, proposal or manual-review bundle and selected actions. Before DAV MOVE the worker rechecks the source, refuses collisions, persists intent, uses `If-Match` and `Overwrite: F`, and verifies destination identity/hash. Graph tags are additive and verified separately. MOVE and tag updates are not one atomic server transaction. Uncertain outcomes remain held; reconciliation reads remote state instead of blindly replaying writes.

Identical-byte duplicate handling is scoped to the authenticated workflow. Recoverable Trash is opt-in and verified. No similarity-based automatic deletion or purge is exposed.

## Processing orchestration boundaries

`Intake.tick` owns the process-wide intake lock and running/stopped lifecycle. `tickSession` verifies identity and scan timing, while `claimableQueue`, `prepareItem` and `handleItemFailure` separate queue recovery/selection, content preparation and retry decisions. Each item uses the current verified session. Pauses, configuration changes and shutdown stop the remaining cohort; busy locks and expired sessions do not consume document retries.

`Workflow.apply` retains approval/evidence checks, job and resource locks, metadata interlocks, automatic authorization and external-location/cross-Space routing. Only after those checks does it call `companion/filing.mjs` for same-Space filing. The strictly checked stage handlers preserve durable intents before MOVE/tag writes and read-only reconciliation without replay. They are internal helpers, not independently authorized API routes. Location traversal is also strictly checked; incomplete or stale snapshots still cannot replace recorded locations. Document reading and final provider-result validation now live in the strictly checked `preparation.mjs`; the journal separates request/cache identity from provider execution and persistence. Exact source, page and rule comparisons remain mandatory. Manual-review fallback, bounded model corrections, literal/date evidence repair and lock-contention decisions use shared typed error codes. Changing or translating a message cannot enable fallback or another request. Plain message lookalikes remain ordinary failures. Historical UI-only diagnoses still recognize old message text without granting processing or writing authority. Non-Error provider failures are recorded as failed attempts rather than leaving running rows. Other orchestration/provider modules remain outside the backend type-check target.

`transactions.mjs` provides the shared synchronous `BEGIN IMMEDIATE` / commit / rollback boundary. It rejects async callbacks, rolls back callback or commit failures and leaves an outer transaction untouched if a nested BEGIN is rejected. Network requests and HTTP responses stay outside the transaction. Runtime ownership retains its process-lifetime transaction, and location snapshots retain their explicit savepoint semantics.

## Journal schema upgrades

`companion/migrations.mjs` owns all persistent production tables, indexes and append-only activity triggers. `ProposalJournal` obtains process ownership before applying migrations and before recovering interrupted reads. Version 1 adopts the released unversioned schema, adds the known historical missing columns, checks the resulting shape and sets SQLite `user_version` in one transaction. Failed upgrades roll back schema changes; newer versions and altered stamped schemas stop startup. Existing records, approvals, fields, tags and uncertain write intents are retained. Demo-only file tables remain isolated in the demo adapter. Backups keep the schema version through SQLite backup/restore. Future changes must append a new numbered migration rather than editing the version-1 baseline.

## Backend contracts

`companion/contracts.d.mts` defines the authenticated actor, processing limits, configuration dependency, file reader, filing stages, document reading, duplicate-suggestion dependencies and logging contracts. The strict `check:companion` target checks seventeen backend modules against Node 22 types; the remaining orchestration, storage and provider modules are not yet claimed as type-checked. Configuration reads validate stored limits before use. Preparation always passes a validated finite byte limit to the source adapter, including when a standalone workflow has no settings service.

## Request and frontend boundaries

Live requests verify account/Space access before buffering the JSON body. The shared request reader enforces declared and streamed byte limits, accepts only JSON objects and returns bounded parse errors without echoing input. Invalid input returns 400; oversized input returns 413 with a closing connection, including chunked requests. Authentication and not-found statuses remain distinct, while existing business-operation holds retain 409. The same-origin POST guard remains ahead of all processing.

The workspace indexes jobs by ID and associates installed review objects with their own job IDs. It no longer serializes a whole document bundle for each lookup or collapses separate attempts with identical contents. Selection follows the previous attempt when present, then the same scoped source. Refreshes discard old associations. The review page shares its target-location state check between path and Space selection.

## Operational logging

The companion emits one JSON record per failure to stderr. Records contain a timestamp, a fixed event name, a bounded error type/code/status and companion source file/line locations. Raw exception messages, full stacks, URLs, document paths/content, account identities and tokens are excluded. API failures after a sent response are logged without sending another response; partial responses close their connection. Unexpected intake-loop failures mark attached scopes as held, with server logs as the fallback if the journal cannot be written. A subsequent successful scan clears the hold. Logs do not authorize retries or replay uncertain writes.

## Deployment

The companion runs without root, with a read-only filesystem, dropped capabilities, private volumes and no published host ports. The proxy forwards Host, Origin and Authorization to a same-origin route. Traefik automation is optional; external proxies need an equivalent route. No raw OpenCloud storage or identity-provider changes are required.

The installer builds the pinned Node image with Poppler/Tesseract, installs matching native assets, checkpoints managed journal state for upgrades and retains rollback evidence. Unknown existing assets and manually managed workers hold installation. See QUICK_INSTALL.md.

## Language extensibility

UI translations, Tesseract OCR packs and document interpretation rules are separate concerns. Data-only interpretation packs provide labels and extraction cues; names and source quotes retain their original script. Unsupported date formats remain review holds. No fixed English/Japanese allowlist is imposed on future packs.

Calendar eras can be added as language-pack data with a format, year offset, first-year label and inclusive Gregorian bounds. Printed source spans remain preserved; interpretation changes only the filing date.

Long preparations survive routine bearer renewal only after a fresh companion status request verifies the same server, account and Space. Workspace-generation changes, sign-out and mismatched identities discard late responses. Intake selects the latest server-verified adapter between documents; HTTP 401/403 holds the cycle without consuming a file attempt or marking the rest failed.

Inbox totals derive from the files currently listed inside the configured inbox. Activity totals retain queue history, including trashed duplicate copies and superseded uploads. Separate client state prevents a history refresh from replacing current Inbox totals.

Evidence repair always stores the actual source span. Unique spacing/Unicode presentation matches can restore quotes and values; an out-of-range page can be recovered only from one matching source page. Date representation changes require a complete printed date in the cited quote and an identical, unambiguous calendar interpretation from the configured language rules. No missing day, month, century or date convention is inferred. Unapproved manual reviews may explicitly request a fresh review revision; earlier reviews remain intact and the new job has no filing authority.

## Import conversion

The managed converter runs on a Docker internal network with the companion, without credentials, persistent mounts, public ports or outbound internet. Only bounded file bytes and allowlisted extensions enter it. Python/Pillow/img2pdf converts images, LibreOffice converts Office documents and MuPDF converts XPS/OXPS. Source files remain in OpenCloud; temporary converter files are removed after each job. Conversion never implies approval or automatic filing.

A scoped durable conversion record binds source resource/ETag/hash, PDF hash and relative archive path. PDF upload uses create-only PUT, then readback verification; original archival uses conditional MOVE without overwrite and verifies resource identity and bytes. Uncertain writes are held and only read-only reconciliation is automatic. Originals are never deleted. PDF copies inherit the Inbox folder permissions; existing original identities and tags remain preserved.

Spreadsheet PDFs use LibreOffice’s local UNO bridge with macros and link updates disabled. Only the in-memory print layout changes: wrapped text, fitted columns and landscape pages; cell values, formulas and number formats are retained. Hidden sheets remain hidden. Recreating an Inbox PDF first creates and verifies a byte-identical previous-PDF backup in OpenCloud. Replacement requires the current ETag and preserved resource ID, and unconfirmed replacement is reconciled read-only. Existing filing approvals block recreation.

## Library browsing and filing controls

All-files browsing reads one folder at a time within the configured filing root and destination Space, authenticating the destination adapter before listing. It includes every format without reading file content, creating a journal proposal, converting, tagging or filing. Filing history keeps its journal search separately. Non-PDF library details offer OpenCloud viewing without a conversion warning. The folder picker reads folders and preserves the draft filename. Tag options combine the authenticated native OpenCloud tag directory and saved workflow tags; choosing or creating a chip only changes the local review draft. Existing evidence-bound approval and metadata save remain the only write actions.

A fresh browser can resolve its workflow Space from the authenticated account's last verified status selection, or its single configured workflow. With no workflow yet, a unique personal Space can bootstrap setup. Ambiguous configured workflows require explicit selection. Every chosen Space still passes current DAV identity/access verification; the client pins the returned Space before loading intake and files. The server-side selection is scoped to origin/account, never caller-supplied account data.

## Optional semantic tag review

Processing settings can opt into AI selection from existing tags or allow new tag candidates. The default remains matching rules only. Preparation reads the authenticated OpenCloud tag directory and saved workflow names into an immutable review snapshot; directory failure stops discovery and no list is silently truncated. A focused second call to the selected tag model compares document subjects/types with the full catalogue, reusing close concepts before proposing new names. Exact source quotations, bounded safe names, source identity and approval digests are still validated. Semantic relevance is a model judgment rather than a keyword guarantee. Review-first waits for approval; only the existing explicitly automatic Tags policy can create/apply tags unattended. Discovery itself performs no Graph writes and does not add inferred terms to saved classification rules.

## Explicit reprocessing and Activity ordering

A user-triggered reprocess creates a new review revision even for an unchanged PDF and unchanged settings. Prior reviews, metadata, source bytes and completed filing records remain intact; no approval carries forward. Filed resources are located by recorded identity before the request, then their current resource ID and ETag are pinned again during preparation. An unresolved filing operation, running preparation, automatic run or metadata intent blocks reprocessing. Reprocessing alone cannot file or tag a document. Activity row actions use durable preparation operations whose results open the new review.

Processing-history columns sort filenames naturally, translated statuses, numbered workflow milestones and numeric attempts. Selecting a sort fetches remaining cursor pages so it orders all processing records rather than only the first page. The chosen order survives polling; selections remain keyed to queue identities.

### Document browsing and filing history

Documents indexes the configured destination through authenticated, one-folder `library-files` reads, at most four concurrent requests. Every folder request rechecks the configured Space and destination boundary. The client discards late responses after account or Space changes, and only publishes the index when every folder succeeds. It reads file metadata and saved field values, without reading document bodies for filtering, preparing reviews, converting files or changing native tags. Search combines normalized words with all selected tags and an optional format. Facets reflect the complete current matching set; selected zero-count tags remain removable. Folder view prunes nonmatching branches while filtering and expands matching ancestors. Presentation pagination does not limit indexing or filter accuracy.

Opening a library row mounts the existing guarded document details editor inline. Dirty, busy and uncertain saves block switching rows and filters. A confirmed save refreshes the metadata index after the editor becomes idle. Document bytes and source identity are checked by the existing detail APIs. Filing records live in Activity’s Filing history tab; legacy Documents `view=filed` bookmarks redirect there. Review has sibling Filing, Fields and Tags sections, with manual tag choices retained in the existing draft and bound to explicit Accept approval.

### Explicit original-format filing and recoverable Trash

`prepare-original` creates a human-only review for an authenticated non-PDF file after its resource ID, ETag and full bytes have been checked. It invokes neither extraction, conversion nor AI. Its `manualReview.reason=original` bundle has no extracted pages or model proposal. Only this exact manual shape permits zero pages; the ordinary PDF and AI evidence validators stay unchanged. Manual destinations must preserve the original extension. Existing digest-bound approval, collision checks, resource locks, metadata holds and cross-Space integrity/recovery checks apply. No automatic authorization can accept this review.

`document-trash` requires explicit client confirmation bound to the current path, resource ID, ETag, full SHA256 and Space. It rechecks identity, configured destination/Inbox or saved-job location, active preparations/filing/bulk operations, metadata intents, source bytes and readable Trash before recording a durable one-shot intent. DELETE uses If-Match. Completion requires absence at the source and one new matching Trash record. Lost responses and restarts use read-only `document-trash-verify`; a different request ID cannot bypass an unresolved intent for the same canonical resource. Metadata saves, preparation and filing approval/application hold while that intent is unresolved. The app does not expose purge. Pending outcomes remain accessible in Activity → Filing history, including when the source is no longer present. Review/metadata history remains intact. Reject only rejects a suggestion and keeps the file; explicit Trash removes the selected copy from the Inbox.

### Metadata definition settings

Fields and saved tag rules use separate keyboard-accessible tabs. Entries expand for editing, with field IDs and matching rules retained in the same unsaved schema across tab switches. Usage counters use an authenticated `metadata-usage` read of the complete configured Documents destination (at most four folders concurrently) and all configured Inbox subfolders. Counts include nonempty saved custom-field values (including numeric zero) and currently applied OpenCloud tags, once per physical document; folders, proposals and keyword aliases are not usage. Incomplete listings, destination changes or stale account responses do not publish partial counts as zero. This read does not process or mutate documents. Removing a definition refreshes its usage first; used and unknown-usage definitions require a modal confirmation. Removing a definition changes only the unsaved settings draft until Save; existing document tags and stored field values remain intact.

The manual destination picker can select a new child folder as a draft. A single normalized safe folder name preserves the document filename; folder creation occurs through the existing explicit Accept workflow. Browsing or cancelling creates no folders or documents.


### Durable background session preference

Verified background adapters are retained separately from browser adapters for intake and backups. Foreground requests and settings saves cannot displace a background adapter. Rotation and detachment use adapter identity so an older credential cannot discard a newer connection. Each scope still authenticates against OpenCloud, including configured manual-only Inbox scopes; neither account nor Space authorization is inferred from client input. Revoked/expired credentials are detached and remain unavailable until a verified connection is attached.

Bulk work with no current session leaves remaining items queued and pauses, rather than marking every item failed. Verified background reconnection resumes queued preparation/conversion operations unless the user has paused intake. Retrying a selected preparation operation resets only its held items, retaining source identity/version pins and completed/cancelled results; it cannot retry filing, conversion or metadata mutations. Reprocessing still requires review-first approval before any real filing/tag writes.


Trash uses the same per-resource lock as PDF preparation, original-format review, metadata and filing operations. PDF preparation holds that lock from its first verified source identity through OCR and inference. The global inference-capacity lock no longer blocks Trash for unrelated documents. Queued/active source, metadata and filing holds remain enforced. A server-confirmed refusal before an intent includes a typed no-intent flag; network failures without that guarantee remain uncertain. The UI performs at most three automatic read-only outcome checks, never repeats DELETE automatically, and exposes a plain status action only if recovery remains unresolved.

## Live document preparation status

Document details and review pages poll a read-only, source-pinned status endpoint. It rechecks current Space access, resource identity and ETag without downloading PDF bytes. Direct and queued PDF preparations record their current stage and bounded failure diagnosis in the private journal. Only a currently owned preparation can be reported as running; abandoned attempts appear interrupted after a restart. Polling never reprocesses, files, reloads metadata or replaces drafts. Scope/navigation changes discard late results, and a lost status connection is shown explicitly.

### External moves within the filing destination

A complete, authenticated metadata-only traversal of the configured filing tree supplies current paths and native tags by exact OpenCloud resource ID. History reads refresh this separate location snapshot before searching/paging; original approvals, source paths, decision dates, fields and evidence remain unchanged. At most four folder reads run concurrently. Incomplete, out-of-bound, duplicate-identity or configuration-changing traversals do not publish partial snapshots. Scope and physical Space are part of lookup; copies cannot inherit metadata or history by name or identical bytes.

Completed reviews can resolve a moved identity within that same destination before preview, reprocessing or read-only verification. Current path identity is checked again after traversal; preview and verification still require the approved full-file hash. Changed contents remain a fresh-review hold, without rewriting the completed filing record. Pending or uncertain write intents continue to use their original pinned paths and cannot gain authority through discovery. Browsing and history refresh on return and every minute while visible; unsaved/busy/uncertain editors and selected history bulk actions are protected. Cross-Space transfers and moves outside the configured filing root are outside this reconciliation scope. No additional service, credential, content extraction or background write is introduced.

### Current processing versus past imports

Activity requests a complete read-only Inbox listing through the same classification used by Inbox. Current work is filtered before pagination by exact resource, ETag and path; old preparations of filed, removed or replaced files remain immutable history. An explicit history toggle exposes those rows as past imports, with their previous outcomes retained and stale actions disabled. Counts continue to describe current work while history is shown. Unresolved filing intents and active preparations remain visible even if their source path is absent. Incomplete or configuration-changing listings fail rather than publishing empty counts. Current-view Retry all filters intake attempts and stopped batch failures against the fresh listing; individual intake retries also recheck resource identity and ETag. No old proposal gains filing authority and no real document is moved or retagged by this reconciliation.

### Processing controls

The UI presents AI analysis and OCR as binary read/preparation capabilities. Review first exposes meaningful Off/Suggest choices for changes. Fully automatic enables the change steps and displays Automated, while OCR remains independently switchable. Tag selection method and application mode share one Tags group. Internal aiInput/aiOutput keys remain compatible, but are no longer separate user choices. Legacy AI-review or OCR-review gates are conservatively projected into review modes for previously automatic writes before editing; saving that projection cannot silently authorize unattended changes. Enabling analysis alone does not bypass source/evidence validation or review choices. Existing values and native tags remain preserved. Presets and custom choices save only explicitly; no server preference is migrated merely by visiting the settings.

### Tag spelling and explicit unassignment

Native catalogue spelling takes precedence for case-insensitive tag lookup. Exact existing names remain selectable when a server already has case variants; ambiguous case-only input requires an explicit exact choice and never merges native tags. Connected Workflow rule saves resolve existing names before persisting. Existing stored rules are not rewritten merely by opening settings. Manual metadata additions resolve names before recording their intent; a failed directory read cannot create an unverified case variant.

`metadata-tag-remove` confirms one exact currently applied tag and pins path, resource, ETag, full hash and metadata version. Under the canonical resource lock it snapshots unchanged fields and remaining tags in the existing metadata intent journal, with a separate removal marker. A single Graph `unassignTags` DELETE contains the resource ID and that tag; it never targets a global tag definition. Completion requires the tag absent, other snapshot tags present and the same canonical resource/full bytes. Read-only reconciliation never resends DELETE. Verified rejection closes the failed attempt only after a fresh state read; uncertain outcomes retain the existing metadata/filing interlock. Source changes and permission loss remain holds. Completed-file verification can use a later explicitly confirmed metadata snapshot, without rewriting the original approval or weakening the full-file hash check. The tag’s remove button directly unassigns it without a second confirmation. Disabled/busy state protects inline document drafts and prevents duplicate submissions.

Processing settings expose Review first and Fully automatic only. Review saves all enabled change steps as suggestions behind review gates, including when every optional change is disabled; it cannot accidentally authorize unattended filing. Fully automatic is explicit and enables all change steps, displayed as fixed Automated states. OCR remains an independent local reading option. One tag selector combines disabled tagging, saved rules, existing-tag AI selection and new-tag suggestions. Existing mixed policies conservatively display as review; only explicit Save changes preferences.

Confirmed metadata writes return the same source snapshot used for readback verification and the committed metadata version. When path, resource, hash and next version match the open document, its panel and library row update in place, preserving the preview and avoiding library traversal. Unknown or stale outcomes use the existing guarded reload/reconciliation path; backend identity, full-byte and tag checks are unchanged.

Turning AI processing off keeps Poppler extraction, Tesseract OCR, custom-field label rules and matching tag rules available. Only AI naming, folder suggestions and semantic tag discovery are disabled, without erasing their saved choices. The companion creates an explicitly manual rules-only review and makes no model requests. It never automatically approves that review. OCR languages and manual editing remain independent.

### Unified processing history

Activity combines current preparation, selectable past imports, expandable source-scoped attempt records and batch history in Processing. Filing history remains a separate tab. Attempt reads omit raw model output and enforce the authenticated workflow scope. Reprocessing pins current identity and ETag and creates a fresh review without filing authority. Direct reprocessing updates only the matching current intake row; earlier proposals and decisions remain immutable.
