# Contributing

Please open an issue describing the problem or proposed change, then send a focused pull request with relevant validation. Follow docs/LOCAL_BUILD.md for checks and packaging.

Keep files and permissions in OpenCloud. Use synthetic fixtures, preserve review/approval boundaries and never add credentials, real documents, personal taxonomies or private deployment details. No cloud fallback or silent truncation of document input. Extend languages through data and tests rather than fixed language lists.

New application code uses AGPL-3.0-only; retain upstream notices. Run domain/UI tests, companion tests, packaging tests, type checks and builds as appropriate. Distinguish source checks from live deployment acceptance. Local development does not authorize changes to a production instance.

Use `pnpm format` before submitting changes; `pnpm format:check` and `pnpm lint` run in CI. Format-only commits are recorded in `.git-blame-ignore-revs`; use `git blame --ignore-revs-file .git-blame-ignore-revs` when tracing behavior. Keep mechanical formatting separate from logic changes. ESLint covers companion, installer, UI and tests; dynamic Vue/API test fixtures still allow existing `any` types, while domain TypeScript does not. Linting is not backend type-checking. `pnpm check:companion` separately runs strict JavaScript/JSDoc checks on the modules listed in `tsconfig.companion.json`, using Node 22 definitions. It currently covers journal migrations, runtime ownership, safe logging, HTTP/health/listen boundaries, processing configuration, pagination, PDF extraction, OCR, same-Space filing stages, filed-location snapshots, document preparation checks, synchronous transactions, duplicate suggestions and request/error handling. Shared domain error codes are checked transitively. The backend target permits only TypeScript syntax that Node can erase directly. Compile-only transaction tests reject Promise-returning callbacks. Other backend modules are not yet type-checked. Expand this list with explicit contracts rather than disabling strict checks.
